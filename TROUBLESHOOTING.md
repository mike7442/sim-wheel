# TROUBLESHOOTING — реальные отказы и что делать

Все пункты ниже — не «теоретически бывает», а то, что уже случалось на этом
стенде. Ищи по симптому.

---

## A. Плата, SWD, прошивка

### A1. `pyocd list` не видит ST-Link

**Причина:** драйвер. ST-Link Utility может работать, а pyOCD — нет, потому что
ему нужен WinUSB/libusb.

**Что делать:**

1. Поставить драйвер ST-LINK (STSW-LINK009).
2. Если не помогло — **Zadig**: Options → List All Devices → ST-Link → WinUSB.
3. Переподключить, `pyocd list` снова.

### A2. `pyocd flash` падает или пишет «no flash algorithm»

**Причина:** у pyOCD нет алгоритма flash для MM32. Это не лечится настройкой.

**Что делать:** прошивать только `mm32flash.py`:

```powershell
python vendor\ALIFE-MM32\tools\mm32flash.py firmware\hoverboard-2026-11-22.bin
```

`pyocd` годится только для `reset -t mm32spin05pf`.

### A3. `mm32flash.py` не видит чип

**Причина:** нет питания на плате. SWD сам плату не питает (и питать от ST-Link
не надо).

**Что делать:** включить БП и штатную кнопку платы, проверить, что земля ST-Link
соединена с землёй платы.

### A4. Прошилось, но плата молчит

**Причина:** чаще всего — мост ESP32 (шаг 5), а не плата.

**Что делать:** сначала loopback 17↔16 и `serial_probe.py`. Если байты ходят —
проверить `baud` в конфиге (должен быть 115200) и `slaveid` (0).

### A5. Прошивка «не влезает» / бинарник больше 31648

**Причина:** GCC 12.2.1. Переполнение +580 байт.

**Что делать:** собрать тулчейном 14.2.1, проверить `arm-none-eabi-gcc --version`.

## B. Связь UART

### B1. `no answer: check wiring, baud and node id`

Порядок проверки:

1. `--boot-delay 4` (ESP32 перезагружается при открытии порта).
2. Перемычка 17↔16 снята (после loopback).
3. `python scripts\serial_probe.py COM4 --seconds 5` — приходят ли вообще байты.
4. Питание платы включено.
5. `baud` в конфиге = 115200 (слово `1152`).

### B2. Приходят байты, но не разбираются

**Причина:** не тот baud или не тот порт.

**Что делать:** попробовать 115200 и 19200 через `serial_probe.py`; убедиться,
что это порт ESP32, а не, например, ST-Link.

### B3. COM-порт исчезает / ESP32 перезагружается при работе мотора

**Причина:** наводка или «плавающая земля» БП (Y-конденсатор).

**Что делать:**

1. Ферритовое кольцо на USB-кабель.
2. Короткий USB-кабель, другой порт (не через хаб).
3. Заземлить корпус БП (PE).
4. Развести силовые и UART-провода подальше друг от друга.

### B4. `lost the board` в середине работы

**Симптом:** скрипт печатает `lost the board`, плата после рестарта чистая,
`errors=0`. Случалось на 0.4 Нм.

**Причина:** потеря линка, не авария платы. Гипотезы по порядку: USB/ESP32,
таймаут 400 мс при подвисании Python, контакт.

**Что делать:**

1. Проверить кабель/порт/кольцо (B3).
2. Временно поднять `timeout` до 600 мс:

```powershell
python scripts\persist.py --boot-delay 4 --set "hoverboard.config.timeout=600"
```

3. Если повторяется на большом моменте — переходить на ESP32-мастер UART
   (PC шлёт только FFB, цикл опроса — на ESP32).

## C. Мотор

### C1. Мотор не крутится, `errors=0`

**Причина:** нет команды или плата не в CLOSED_LOOP.

**Что делать:** `persist.py --show` → `state` должен быть 8 во время движения.
Проверить, что `spin.py` реально шлёт (в выводе есть скорость).

### C2. Крутится рывками, гудит «не в фазе»

**Причина:** неверный порядок/инверсия Холлов. У нас было именно так:
PC13/14/15 без инверсии.

**Что делать:** PinFinder `detect hall`, сохранить. Правильный результат для
этой платы: `A=PC14 B=PC15 C=PC13 invert=1`.

### C3. Крутится не в ту сторону

**Причина:** порядок фаз или знак команды.

**Что делать:** для проверки — отрицательная скорость. Если в игре ось/момент
наоборот — `--invert-axis` / `--invert-torque`, а не перепайка.

### C4. Крутится, но момента нет

**Причина:** `drivemode` не 10 (например, speed).

**Что делать:**

```powershell
python scripts\persist.py --boot-delay 4 --drivemode 10 --save
```

Снять/подать питание, проверить `--show`.

### C5. Момент есть, но слабый / несимметричный

**Причина:** ограничение тока или `vel_limit`.

**Что делать:** `--show` → `current_soft_max` (10 А), `vel_limit` (5 об/с).
Проверить `I_q`: если он упирается в лимит, момент не вырастет.

### C6. Мотор греется в покое с моментом

**Это нормально.** Момент в стену = ток течёт, мощность греет обмотки. Не держать
долго на большом моменте.

## D. Конфиг и питание

### D1. На 42 В плата уходит в coast, `DC_BUS_OVER_VOLTAGE`

**Причина:** `batfull` низкий. Прошивка уходит в coast уже при `batfull+3000`.

**Что делать:** поднять `batfull` до `vbus − 100` мВ:

```powershell
python scripts\persist.py --boot-delay 4 --set "config.dc_bus_overvoltage_trip_level=44.9" --save
```

### D2. `DC_BUS_UNDER_VOLTAGE`

**Причина:** `batempty` выше фактического напряжения (например, 30000 при БП 24 В).

**Что делать:** `--set "hoverboard.config.batempty=18000"`.

### D3. Настройки сбрасываются после снятия питания

**Причина:** не было `--save` / не прошла запись flash.

**Что делать:** `--save`, дождаться `saved`, снять питание, проверить `--show`.
Или восстановить снапшот целиком (GUIDE §9).

### D4. После restore `--diff` показывает расхождения

**Причина:** часть слов не легла (плата была armed, плохой контакт, питание).

**Что делать:** плата должна быть disarmed; повторить restore; посмотреть, какие
именно слова не легли, и записать их вручную через `--set`.

## E. vJoy и FFB

### E1. `Cannot acquire vJoy Device because it is not in VJD_STAT_FREE`

**Причина:** устройство уже занято другим процессом (обычно старый скрипт).

**Что делать:**

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Select-Object ProcessId,CommandLine
Stop-Process -Id <pid>
```

Один процесс на устройство vJoy.

### E2. `ffb_supported()` возвращает `False`

**Причина:** FFB не включён для устройства в vJoyConf.

**Что делать:** vJoyConf → устройство 1 → **Enable FFB** → Apply.

### E3. `ffb` всегда 0.000 в заезде

Порядок:

1. FFB включён в настройках игры?
2. Устройство vJoy выбрано для руля?
3. Ты **в заезде**, а не в меню?
4. Скрипт запущен **до** игры?
5. В vJoyConf включён FFB?
6. Запусти `ffb_test.py` — если момент есть, проблема в игре/vJoy, не в моторе.

### E4. Момент «залипает» после выхода из игры

**Причина:** эффект остановлен, но последний magnitude остался.

**Что делать:** в `vjoy_ffb.py` это уже обработано (stop/reset/block free →
момент 0). Если используешь свой скрипт — обрабатывать reptype 10/11/12, а не
только 5.

### E5. Колесо звенит, дёргается, раскачивается

**Причина:** петля FFB в резонансе из-за задержки.

**Что делать по порядку:**

1. `Ctrl+C`.
2. `--ffb-smoothing 0.15`.
3. `--max-torque` меньше.
4. `--ffb-deadzone` больше (например 300).
5. Поднять частоту (baud 460800) или ESP32-мастер.

### E6. Руль в игре крутится не в ту сторону

**Что делать:** `--invert-axis`. Если момент тянет от поворота — `--invert-torque`.

### E7. Ось стоит не в центре / упирается раньше

**Причина:** `range_deg` не совпадает с механикой или скрипт запущен, когда руль
был не в нейтрали.

**Что делать:** поставить руль в нейтраль, перезапустить скрипт, выставить
`--range-deg` по реальному ходу.

## F. Сборка

### F1. `make: command not found`

```powershell
winget install --id ezwinports.make -e
```

Закрыть/открыть терминал.

### F2. `sh: command not found` / `tr: command not found`

Собирать в **Git Bash**, а не в PowerShell. Git for Windows даёт `sh`, `tr`, `cmp`.

### F3. `vendor/ALIFE-MM32` отсутствует

```powershell
powershell -ExecutionPolicy Bypass -File scripts\fetch_vendor.ps1
```

### F4. `ModuleNotFoundError: cansimple_uart`

Скрипты ищут `vendor/ALIFE-MM32/tools`. Проверить, что vendor склонирован и
запуск идёт из корня репозитория.

### F5. `ModuleNotFoundError: pyvjoy`

Поставлен не тот пакет. Нужен **`pyvjoyffb`** (модуль `pyvjoy` с FFB):

```powershell
python -m pip uninstall pyvjoy
python -m pip install pyvjoyffb
```

## G. Быстрая диагностика одной командой

```powershell
python scripts\persist.py --boot-delay 4 --show
```

Читается так:

| Поле | Норма | Если нет |
|---|---|---|
| `version.protocol` | 2 | не тот порт/baud |
| `heartbeat.errors` | 0 | см. REFERENCE §5 |
| `heartbeat.state` | 1 в покое | 8 = armed, сначала disarm |
| `drivemode` | 10 | `--drivemode 10 --save` |
| `commutation` | 2 | FOC не включён |
| `control_mode` | 1 | не torque |
| `vbus` | ~42 | питание/делитель |
| `batfull` | 41900 | coast на 42 В |
| `vel_limit` | 5.0 | момент гаснет раньше |
